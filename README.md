# Поиск простых чисел в заданном диапазоне

Командный учебный проект на языке **C++** по реализации и сравнению алгоритмов поиска простых чисел.

Каждый участник разрабатывает собственный алгоритм в отдельном файле. Общая программа запускает все реализованные алгоритмы на одинаковых входных данных, проверяет корректность результатов и измеряет время выполнения.

## 1. Цель и задачи проекта

**Цель:** разработать программу для поиска простых чисел в заданном пользователем диапазоне с использованием различных алгоритмов и провести сравнительный анализ их производительности.

**Основные задачи:**

1. Реализовать шесть алгоритмов поиска простых чисел.
2. Разработать единый интерфейс для подключения алгоритмов.
3. Организовать ввод границ диапазона пользователем.
4. Проверить корректность работы каждого алгоритма.
5. Реализовать измерение времени выполнения алгоритмов.
6. Сравнить эффективность алгоритмов на различных диапазонах.

## 3. Единый контракт алгоритмов

Для совместимости все алгоритмы должны иметь одинаковые типы входных параметров и возвращаемого значения.

**Общий вид функции:**

```cpp
std::vector<int> findPrimes(int left, int right);
```

**Параметры:**

- `left` — левая граница диапазона.
- `right` — правая граница диапазона.

Обе границы включаются в поиск.

**Возвращаемое значение:**

`std::vector<int>` — вектор найденных простых чисел, отсортированных по возрастанию.

### Обязательные требования

1. Функция принимает два параметра типа `int`.
2. Возвращает результат типа `std::vector<int>`.
3. Возвращает только простые числа.
4. Числа в результате расположены по возрастанию.
5. Повторяющиеся значения отсутствуют.
6. Числа меньше 2 не считаются простыми.
7. Если простых чисел нет, возвращается пустой вектор.
8. Если `left > right`, возвращается пустой вектор.
9. Функция не выполняет ввод и вывод через `cin` и `cout`.
10. Функция не изменяет данные за пределами собственной реализации.

### Названия функций участников

Для исключения конфликтов имён каждый алгоритм получает отдельное название функции:

```cpp
std::vector<int> findPrimesTrialDivision(int left, int right);

std::vector<int> findPrimesEratosthenes(int left, int right);

std::vector<int> findPrimesSegmented(int left, int right);

std::vector<int> findPrimesSundaram(int left, int right);

std::vector<int> findPrimesAtkinBernstein(int left, int right);

std::vector<int> findPrimesMillerRabin(int left, int right);
```

Названия и сигнатуры функций должны точно соответствовать указанным объявлениям.




## 4. Как участнику подключить свой алгоритм

**Шаг 1. Создать файл алгоритма**

Каждый участник создаёт собственный `.cpp` в папке `algorithms` согласно таблице распределения.

Файл необходимо добавить в проект Visual Studio:

`Обозреватель решений → Проект → Добавить → Существующий элемент`

**Шаг 2. Реализовать функцию**

Функция должна соответствовать контракту проекта.

Например, для метода пробного деления:

```cpp
#include <vector>
#include "../Participants.h"

std::vector<int> findPrimesTrialDivision(int left, int right)
{
    std::vector<int> primes;

    // Реализация алгоритма

    return primes;
}
```

Это шаблон функции, а не готовая реализация метода.

**Шаг 3. Подключить алгоритм**

После реализации участник сообщает капитану команды о готовности алгоритма.

Капитан проверяет функцию, её объявление в `Participants.h` и регистрацию в `Participants.cpp`.

Чтобы исключить конфликты при совместной работе, общие файлы подключения алгоритмов изменяет капитан.

## 5. Сравнение производительности

После реализации всех алгоритмов проводится сравнение времени их выполнения.

Каждый алгоритм запускается на одинаковых диапазонах.

Планируемые тестовые диапазоны:

- [1; 100]
- [1; 1 000]
- [1; 10 000]
- [1; 100 000]
- [1; 1 000 000]

Дополнительные диапазоны выбираются с учётом ограничений памяти и времени выполнения алгоритмов.

Время измеряется без учёта операций пользовательского ввода и вывода.

Для уменьшения влияния случайных колебаний производительности предполагается выполнять несколько повторных запусков и рассчитывать итоговое время.

### Формат результатов

Программа должна выводить таблицу со следующими данными:

```text
dataset  left  right  algorithm  author  count  time_us  status
```

Где:

- `dataset` — название тестового набора.
- `left`, `right` — границы диапазона.
- `algorithm` — название алгоритма.
- `author` — разработчик алгоритма.
- `count` — количество найденных простых чисел.
- `time_us` — время выполнения в микросекундах.
- `status` — результат проверки (`OK` или `FAIL`).

Планируется сохранение результатов в `result.txt` для дальнейшего построения графиков и сравнительного анализа.

После создания и подключения файлов проекта:

3. Выбрать конфигурацию `Release`.
4. Собрать проект.
5. Запустить программу сочетанием `Ctrl+F5`.

Все алгоритмы должны запускаться через общую программу.

## 7. Правила работы 

Основная ветка проекта — `main`.

Каждый участник работает в своей ветке:

```text
main
│
├── feature/trial-division
├── feature/eratosthenes
├── feature/segmented-sieve
├── feature/sundaram
├── feature/atkin-bernstein
└── feature/miller-rabin
```

### Начало работы участника

1. Клонировать репозиторий на компьютер.
2. Получить актуальную версию ветки `main`.
3. Создать собственную ветку для алгоритма.
4. Открыть решение Visual Studio.

### Рабочий процесс

1. Написать или изменить код своего алгоритма.
2. Собрать проект.
3. Выполнить проверку на тестовых данных.
4. Убедиться в отсутствии ошибок.
5. Создать коммит с описанием изменений.
6. Отправить изменения в свою ветку GitHub.
7. Создать Pull Request для объединения с `main`.
8. Дождаться проверки и принятия изменений капитаном.

**Основные правила:**

- Каждый участник разрабатывает алгоритм в отдельном `.cpp`.
- Изменения других алгоритмов без согласования не допускаются.
- В ветку `main` участники напрямую изменения не отправляют.
- Общие файлы интеграции изменяются капитаном.
- Коммиты должны содержать понятные описания.
- Неработающий код не должен объединяться с основной веткой.
- Ошибки и дополнительные задачи фиксируются через GitHub Issues.
- Рабочие ветки после объединения сохраняются.
